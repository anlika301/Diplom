## Схема 2: `ods_bak` — Operational Data Store (текущее состояние)

Та же информация что в STG, но с типизацией и с гарантией "одна строка = один объект". При повторной загрузке строки **обновляются**, а не дублируются. Здесь аналитика не строится — это промежуточный слой для подготовки данных в DDS.

### `ods_bak.applications`
Ключевые отличия от STG: `app_id` вместо `id`, `priority` стал `INTEGER`, добавлен `updated_at`.

### `ods_bak.scores`
Числа типизированы: `score_without_vi INTEGER`, `all_vi_passed BOOLEAN`, `rank1`…`rank13` — `NUMERIC(10,4)`. Строка `"Да"` → `TRUE`, `"1 234,56"` → `1234.56`.

### `ods_bak.contracts`
`ege INTEGER`, `individual_achievements INTEGER`, `total NUMERIC(14,2)`. Поле `payment_status` остаётся TEXT — строковый статус.

### `ods_bak.criteria`
Идентична STG по структуре, но с `updated_at`.

## Схема 3: `dds_bak` — Detailed Data Store (нормализация + история)

Это самое важное. Данные приведены к **3NF**: справочники вынесены отдельно, факты ссылаются на них через суррогатные ключи. История изменений хранится через **SCD Type 2**.

---

### `dds_bak.dim_applicants` — справочник абитуриентов

**Одна строка = один уникальный абитуриент.** Собирается из всех трёх ODS-таблиц одновременно — абитуриент может быть в заявлениях, баллах и договорах одновременно, берём один "профиль".

| Поле | Тип | Описание |
|---|---|---|
| `applicant_id` | BIGSERIAL **PK** | Суррогатный ключ, генерируется БД автоматически |
| `code_applicant` | TEXT UNIQUE NOT NULL | Натуральный ключ — код абитуриента из CSV |
| `full_name` | TEXT | ФИО |
| `city` | TEXT | Город кампуса |
| `uniq_code` | TEXT | Уникальный код поступающего |
| `created_at` | TIMESTAMP | Когда появился в системе |
| `updated_at` | TIMESTAMP | Когда последний раз обновился |

**Почему нужна:** чтобы не хранить ФИО в каждой строке заявления, балла и договора. Один абитуриент → один `applicant_id` → все его заявления и договоры через этот FK.

---

### `dds_bak.dim_programs` — справочник программ

**Одна строка = одна уникальная образовательная программа в конкретном городе.**

| Поле | Тип | Описание |
|---|---|---|
| `program_id` | BIGSERIAL **PK** | Суррогатный ключ |
| `program` | TEXT | Название программы |
| `specialization` | TEXT | Специализация внутри программы |
| `city` | TEXT | Город кампуса |
| `created_at` | TIMESTAMP | — |
| `updated_at` | TIMESTAMP | — |

**Уникальность** по тройке `(program, specialization, city)` — например "Экономика / Москва" и "Экономика / Санкт-Петербург" это **разные** программы с разными `program_id`.

**Почему нужна:** 170 уникальных программ, абитуриент подаёт заявления на несколько — без справочника название программы повторялось бы в каждой из 44 648 строк заявлений и 57 030 строк баллов.

---

### `dds_bak.dim_criteria` — справочник критериев отбора

**Одна строка = правила приёма на конкретную программу.**

| Поле | Тип | Описание |
|---|---|---|
| `criteria_id` | BIGSERIAL **PK** | Суррогатный ключ |
| `program_id` | BIGINT **FK NOT NULL** | Ссылка на `dim_programs` |
| `scep` | TEXT UNIQUE NOT NULL | Натуральный ключ — код "сцепки" |
| `direction` | TEXT | Направление подготовки (укрупнённое) |
| `criteria_value` | TEXT | Сам критерий — например минимальный балл |
| `created_at` / `updated_at` | TIMESTAMP | — |

**Почему нужна:** 72 критерия привязаны к программам через `program_id`. Можно сделать запрос "покажи критерии для программы Экономика в Москве".

---

### `dds_bak.fact_applications` — факт заявлений (SCD Type 2)

**Одна строка = одна версия заявления абитуриента на программу.** При изменении `sspvo_status` или `priority` старая строка закрывается, создаётся новая.

| Поле | Тип | Описание |
|---|---|---|
| `application_dds_id` | BIGSERIAL **PK** | Суррогатный ключ версии |
| `app_id` | TEXT | Натуральный ключ (из CSV) |
| `applicant_id` | BIGINT **FK NOT NULL** | Ссылка на абитуриента |
| `program_id` | BIGINT **FK NOT NULL** | Ссылка на программу |
| `valid_from` | DATE | С какой даты актуальна эта версия |
| `valid_to` | DATE | По какую дату (NULL = актуальна сейчас) |
| `is_current` | BOOLEAN | TRUE = текущая версия |
| `priority` | INTEGER | Приоритет заявления (1 = самый желаемый) |
| `reg_number` | TEXT | Регистрационный номер |
| `uniq_code` | TEXT | Уникальный код |
| `sspvo_status` | TEXT | Статус в системе ССПВО — **отслеживается** |

**Как работает история:** абитуриент подал заявление 1 мая со статусом "Подано". 10 мая статус изменился на "Зачислен". В таблице будет **две строки**:

```
app_id  | sspvo_status | valid_from | valid_to   | is_current
--------|-------------|------------|------------|----------
А-001   | Подано      | 2026-05-01 | 2026-05-10 | FALSE
А-001   | Зачислен    | 2026-05-10 | NULL       | TRUE
```

---

### `dds_bak.fact_scores` — факт баллов и рейтингов (SCD Type 2)

**Одна строка = одна версия записи о баллах абитуриента на программу.** Отслеживаются `rank2`, `rank3`, `rank4`, `rank5`, `rank6` — рейтинговые позиции меняются ежедневно в процессе приёма.

| Поле | Тип | Описание |
|---|---|---|
| `score_dds_id` | BIGSERIAL **PK** | Суррогатный ключ версии |
| `nomer` | TEXT | Натуральный ключ |
| `applicant_id` | BIGINT **FK NOT NULL** | Абитуриент |
| `program_id` | BIGINT **FK NOT NULL** | Программа |
| `valid_from` / `valid_to` / `is_current` | — | SCD2-поля |
| `priority` | INTEGER | Приоритет |
| `score_without_vi` | INTEGER | Балл без ВИ |
| `all_vi_passed` | BOOLEAN | Все вступительные пройдены |
| `rank1`…`rank13` | NUMERIC(10,4) | Рейтинговые позиции по разным критериям |

**rank1-rank13** — это разные способы подсчёта рейтинга (по ЕГЭ, с ВИ, без ВИ, БВИ и т.д.). Большинство абитуриентов имеют значения только в 5-6 из них — остальные NULL.

---

### `dds_bak.fact_contracts` — факт договоров (SCD Type 2)

**Одна строка = одна версия договора о зачислении.** Отслеживаются `payment_status` и `total` — статус оплаты и итоговая сумма могут меняться.

| Поле | Тип | Описание |
|---|---|---|
| `contract_dds_id` | BIGSERIAL **PK** | Суррогатный ключ версии |
| `dogovor` | TEXT | Номер договора |
| `applicant_id` | BIGINT **FK NOT NULL** | Абитуриент |
| `program_id` | BIGINT **FK NOT NULL** | Программа |
| `valid_from` / `valid_to` / `is_current` | — | SCD2-поля |
| `id_application` | TEXT | ID связанного заявления |
| `priority` | INTEGER | Приоритет |
| `admission_plan` | TEXT | Plan приёма (бюджет/платное/квота) |
| `payment_status` | TEXT | Статус оплаты — **отслеживается** |
| `name_parent` | TEXT | ФИО родителя (для несовершеннолетних) |
| `number_parent` | TEXT | Телефон родителя |
| `bvi` | TEXT | БВИ-льгота |
| `ege` | INTEGER | Сумма баллов ЕГЭ |
| `individual_achievements` | INTEGER | Баллы за ИД |
| `total` | NUMERIC(14,2) | Итоговый конкурсный балл — **отслеживается** |
| `uniq_code` | TEXT | Уникальный код |

## Схема 4: `mart_bak` — витрины (только вьюхи, без таблиц)

Это не таблицы, а **SQL-представления** поверх DDS — только для чтения. Аналитик пишет запрос к витрине и получает готовый результат без JOIN-ов.

| Вьюха | Что показывает |
|---|---|
| `v_applications` | Текущие заявления с ФИО, программой, статусом ССПВО |
| `v_contracts` | Текущие договоры с баллами, статусом оплаты, контактами |
| `v_scores` | Текущие баллы и рейтинги с ФИО и программой |
| `v_payment_summary` | Сводка по оплатам: сколько договоров, средняя и общая сумма по программам |
| `v_admission_stats` | Статистика по программам: кол-во абитуриентов, заявлений, договоров, лучший/худший/средний ранг |
| `v_contract_history` | **Полная история** изменений договоров — все SCD2-версии со старыми и новыми статусами |
